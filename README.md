# Приложение для учёта личных финансов

Это учебный проект по курсу ООП на Java, выполненный по заданию PROMO IT. В приложении можно записывать доходы и расходы, задавать бюджеты и смотреть, сколько денег осталось. Работа с программой идёт через команды в терминале.

У каждого пользователя свой аккаунт и кошелёк. Во время работы данные хранятся в памяти, а при выходе сохраняются в файл.

## Что умеет приложение

- Регистрировать пользователей и проверять логин с паролем.
- Добавлять доходы и расходы по категориям.
- Создавать и переименовывать категории, менять их бюджеты.
- Показывать баланс, историю операций и остаток бюджета.
- Считать доходы и расходы по нескольким категориям или за выбранный период.
- Предупреждать о приближении к лимиту, перерасходе и нулевом балансе.
- Переводить деньги между кошельками пользователей.
- Сохранять отчёты в текстовый файл или CSV, выгружать и загружать кошелёк в JSON.

## Как запустить

Нужен **JDK 17**. Для сборки используется Maven. Устанавливать его отдельно не обязательно: в проекте есть Maven Wrapper, который скачает Maven и нужные библиотеки. При первой сборке потребуется интернет.

Сначала скачайте проект или клонируйте репозиторий:

```text
git clone https://github.com/Marfines/personal-finance.git
```

Откройте терминал в папке проекта — там, где находится `pom.xml`.

**Windows, командная строка cmd:**

```bat
set "JAVA_HOME=C:\Program Files\Java\jdk-17"
mvnw.cmd verify
"%JAVA_HOME%\bin\java.exe" -jar target\personal-finance.jar
```

**Windows, PowerShell:**

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-17'
.\mvnw.cmd verify
& "$env:JAVA_HOME\bin\java.exe" -jar target/personal-finance.jar
```

Путь к JDK в примерах нужно заменить на свой, если Java установлена в другой папке. Команды для cmd и PowerShell отличаются: символ `&` нужен только в примере для PowerShell.

**Linux/macOS** — Java 17 должна быть доступна в терминале:

```sh
sh mvnw verify
java -jar target/personal-finance.jar
```

После сборки готовое приложение находится в `target/personal-finance.jar`. При следующих запусках достаточно команды с `java`, заново собирать проект не нужно.

Можно запустить и через IntelliJ IDEA: открыть `pom.xml`, выбрать JDK 17 и запустить класс `ru.promo.finance.Main`.

## Как пользоваться

Для начала создайте пользователя:

```text
register oleg
```

Программа отдельно попросит пароль. Он должен содержать от 8 до 128 символов. В обычном терминале ввод пароля скрыт — это нормально. В консоли IDE символы могут отображаться.

После регистрации войдите в аккаунт:

```text
login oleg
```

Введите тот же пароль. Теперь можно создать категории и добавить операции:

```text
category add Зарплата
category add Еда
income Зарплата 20000
budget set Еда 4000
expense Еда 300
report
exit
```

В этом примере доход составит 20 000 рублей, расход — 300 рублей, баланс — 19 700 рублей. На еду останется 3 700 рублей из установленного бюджета.

## Команды

В самом приложении список команд можно посмотреть через `help`. Параметры в квадратных скобках необязательные, сами скобки вводить не нужно.

| Команда | Что делает |
| --- | --- |
| `help` | Показывает справку |
| `register <логин>` | Создаёт пользователя |
| `login <логин>` | Выполняет вход |
| `logout` | Сохраняет данные и выходит из аккаунта |
| `category add <название>` | Создаёт категорию |
| `category rename <старое> <новое>` | Меняет название категории и в истории операций |
| `category delete <название>` | Удаляет категорию, если в ней ещё нет операций |
| `categories` | Показывает категории и их бюджеты |
| `budget set <категория> <сумма>` | Устанавливает или меняет бюджет |
| `budget clear <категория>` | Убирает ограничение бюджета |
| `income <категория> <сумма> [дата] [комментарий]` | Добавляет доход |
| `expense <категория> <сумма> [дата] [комментарий]` | Добавляет расход |
| `transfer <логин> <сумма>` | Переводит деньги другому пользователю |
| `report [фильтры] [--file <файл>]` | Показывает сводку или записывает её в файл |
| `history [фильтры] [--file <файл>]` | Показывает историю или записывает её в файл |
| `alerts` | Показывает текущие предупреждения |
| `export json <файл>` | Сохраняет копию текущего кошелька |
| `export csv <файл> [фильтры]` | Выгружает операции в CSV |
| `import json <файл> --replace` | Заменяет текущий кошелёк данными из JSON |
| `save` | Сохраняет данные без выхода |
| `exit` или `quit` | Сохраняет данные и закрывает приложение |

Категорию нужно создать до добавления операции. Названия с пробелами и комментарии заключаются в кавычки:

```text
category add "Коммунальные услуги"
expense "Коммунальные услуги" 3000 2026-01-15 "Оплата квартиры"
```

Дата указывается в формате `ГГГГ-ММ-ДД`. Если её пропустить, используется сегодняшний день. Чтобы добавить комментарий с сегодняшней датой, вместо даты поставьте `-`:

```text
expense Еда 500 - "Покупка продуктов"
```

Примеры отчётов и фильтров:

```text
report --categories "Еда,Такси"
report --from 2026-01-01 --to 2026-01-31
report --categories Еда --from 2026-01-01 --to 2026-01-31
report --file report.txt
history --file history.txt
```

Обе даты входят в период. Если категория не найдена или за период нет операций, программа сообщит об этом. Для названия с запятой есть отдельный параметр: `--category "Еда, продукты"`. Его можно повторять для нескольких категорий.

## Несколько правил работы

Все суммы указаны в рублях. Можно вводить `1500.50` или `1500,50`, но не больше двух знаков после запятой. Для расчётов используется `BigDecimal`, чтобы не терять точность при работе с деньгами.

Логин должен содержать от 3 до 32 латинских букв, цифр, символов `_` или `-`. Регистр логинов и категорий не учитывается. Сумма операции должна быть положительной, а бюджет можно установить равным нулю. Операции с будущей датой добавить нельзя.

Бюджет считается за всё время и не сбрасывается каждый месяц. В отчёте с фильтром дат остаток считается относительно расходов за выбранный период. При этом баланс кошелька и предупреждения всегда учитывают всю историю.

Программа предупреждает, когда потрачено 80% бюджета, лимит исчерпан или превышен. Также есть сообщения о нулевом балансе и о том, что расходы превысили доходы. Записать расход при отрицательном балансе можно, а для перевода денег должно хватать.

Для перевода получатель должен быть зарегистрирован. Например, `transfer anna 1000` запишет расход у отправителя и доход у пользователя `anna`. Категория `Переводы` создаётся автоматически. Перевод самому себе запрещён.

## Сохранение и файлы

Данные пользователей и кошельков сохраняются в `data/finance.json`. При следующем запуске программа читает этот файл, и после входа пользователь получает свой кошелёк.

Сохранение происходит при командах `save`, `logout`, `exit`, `quit` и при завершении входного потока. Если просто закрыть окно или принудительно остановить программу, последние изменения могут потеряться. Поэтому лучше выходить через `exit`.

Пароли хранятся в виде хешей с солью. Сам файл с финансовыми данными не зашифрован. Папки с рабочими данными и результатами сборки исключены из Git.

Кошелёк можно отдельно выгрузить и восстановить:

```text
export json wallet-backup.json
export csv operations.csv
import json wallet-backup.json --replace
```

Экспорт создаёт новый файл, существующий файл он не перезаписывает. Если указан путь к папке, она уже должна существовать. Обратная загрузка поддерживается для JSON.

Импорт с `--replace` заменяет текущий кошелёк, поэтому перед ним стоит сделать копию. Менять операции переводов через импорт нельзя: иначе данные отправителя и получателя перестанут совпадать. Для восстановления всех кошельков вместе нужна копия `data/finance.json`; заменять её следует при закрытой программе.

## Как проверить проект

В проекте **46 тестов на JUnit 5**. Они проверяют расчёты, авторизацию, отдельные кошельки пользователей, категории, бюджеты, переводы, работу с файлами и обработку неверных команд.

Из папки проекта в cmd:

```bat
mvnw.cmd test
```

Полная проверка — тесты, сборка JAR и проверка оформления кода:

```bat
mvnw.cmd verify
```

В PowerShell используйте `.\mvnw.cmd`, в Linux/macOS — `sh mvnw`. Для форматирования Java-кода есть команда `mvnw.cmd spotless:apply`. Результаты тестов находятся в `target/surefire-reports/`. Тесты работают с отдельными данными и не меняют настоящий кошелёк.

Та же проверка автоматически запускается в [GitHub Actions](https://github.com/Marfines/personal-finance/actions) при загрузке изменений.

Пример из ТЗ можно повторить по файлу [examples/demo.commands](examples/demo.commands). В нём есть регистрация учебного пользователя и все нужные операции. Для автоматического запуска в cmd используйте отдельный, ещё не использованный каталог данных:

```bat
"%JAVA_HOME%\bin\java.exe" -jar target\personal-finance.jar --data-dir data/example < examples\demo.commands
```

Ожидаемый результат: общий доход — **63 000**, расходы — **8 300**, баланс — **54 700** рублей. Остаток бюджета на еду — **3 200**, на развлечения — **0**, на коммунальные услуги — **−500** рублей.

## Как устроен код

Код разделён на три части:

| Папка | Что в ней находится |
| --- | --- |
| `core` | Кошелёк, категории, операции и основная логика: вход, расчёты, бюджеты и переводы |
| `infra` | Работа с файлами JSON и CSV, хеширование паролей |
| `cli` | Чтение команд, проверка их формата и вывод в терминал |

Точка входа — `Main.java`. Основные классы находятся в `src/main/java/ru/promo/finance`, тесты — в `src/test/java`. Для хранилища есть интерфейс `StateRepository`: в приложении используется файл, а в части тестов — данные в памяти.

Для JSON используется Jackson, для тестов — JUnit. Зависимости и их версии указаны в `pom.xml`; Maven скачивает их сам, вручную устанавливать библиотеки не нужно.

Подробнее о классах и их назначении написано в [описании архитектуры](docs/ARCHITECTURE.md). Также есть [список выполненных требований](docs/REQUIREMENTS.md) и [результаты проверки](docs/VALIDATION.md).
