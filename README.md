# Личные финансы — Java CLI

Backend-приложение по ТЗ PROMO IT для курса ООП: несколько пользователей, кошельки, доходы и расходы, бюджеты, статистика и переводы. Взаимодействие через терминал. Во время работы данные находятся в памяти; при сохранении записывается JSON-файл. База данных и веб-сервер не требуются.

## Быстрый запуск

Требуется **JDK 17** (проект проверен на Java 17). Maven устанавливать отдельно не нужно: официальный Maven Wrapper включён в репозиторий. Для первой сборки нужен интернет; Maven автоматически скачает зависимости из Maven Central. При наличии Maven 3.9+ можно заменить вызов wrapper на `mvn`.

Windows, PowerShell из корня проекта:

```powershell
# Укажите путь к своему JDK, если JAVA_HOME ещё не настроен:
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-17'
.\mvnw.cmd verify
& "$env:JAVA_HOME\bin\java.exe" -jar target/personal-finance.jar
```

Linux/macOS:

```sh
sh mvnw verify
java -jar target/personal-finance.jar
```

Windows, обычная командная строка **cmd** (в ней не используется символ `&`):

```bat
cd /d "C:\path\to\personal-finance"
set "JAVA_HOME=C:\Program Files\Java\jdk-17"
mvnw.cmd verify
"%JAVA_HOME%\bin\java.exe" -jar target\personal-finance.jar
```

Замените путь к проекту и JDK на свои.

Сборка создаёт `target/personal-finance.jar`, включающий библиотеки. Для запуска готового JAR нужен только Java runtime 17+. Собственный каталог хранения:

```sh
java -jar target/personal-finance.jar --data-dir ./data/demo
```

В IntelliJ IDEA откройте `pom.xml`, выберите SDK 17, запустите `ru.promo.finance.Main`. В обычном терминале пароль вводится скрыто; консоль IDE может показывать ввод. Для перенаправленного ввода/вывода используется UTF-8.

## Первое использование

Введите `register alice`. На отдельный запрос `Пароль:` задайте пароль длиной от 8 до 128 символов. Затем введите `login alice` и тот же пароль. Пароль не передаётся аргументом команды.

В терминале символы пароля не отображаются. Пароль `12345` не подходит: в нём только пять символов.

```text
category add Зарплата
category add Еда
income Зарплата 20000
budget set Еда 4000
expense Еда 300 - "Покупка продуктов"
report
history
save
exit
```

`-` означает сегодняшнюю дату. Вместо него можно указать `2026-01-15`. Даты будущего для операций запрещены. Названия с пробелами заключайте в двойные или одинарные кавычки.

## Команды

| Команда | Назначение |
| --- | --- |
| `help` | Справка и примеры |
| `register <логин>` | Регистрация; пароль вводится отдельно |
| `login <логин>` | Вход и восстановление кошелька из загруженного снимка |
| `logout` | Сохранение всех данных и выход из аккаунта |
| `category add <название>` | Создание категории |
| `category rename <старое> <новое>` | Переименование вместе с операциями и бюджетом |
| `category delete <название>` | Удаление категории, если в ней нет операций |
| `categories` | Категории и лимиты |
| `budget set <категория> <лимит>` | Создание или изменение бюджета |
| `budget clear <категория>` | Удаление лимита |
| `income <категория> <сумма> [дата или -] [комментарий]` | Доход |
| `expense <категория> <сумма> [дата или -] [комментарий]` | Расход |
| `transfer <логин> <сумма>` | Перевод другому зарегистрированному пользователю |
| `report [фильтры] [--file <путь>]` | Доходы, расходы, баланс, бюджеты и остатки |
| `history [фильтры] [--file <путь>]` | Список операций |
| `alerts` | Текущие предупреждения |
| `export json <путь>` | Снимок текущего кошелька, без учётных данных |
| `export csv <путь> [фильтры]` | Отчёт по операциям в CSV |
| `import json <путь> --replace` | Замена текущего кошелька проверенным снимком |
| `save` | Сохранение всех пользователей и кошельков |
| `exit` / `quit` | Сохранение и завершение |

Фильтры можно сочетать:

```text
report --categories "Еда,Такси"
report --from 2026-01-01 --to 2026-01-31
report --categories "Еда,Коммунальные услуги" --from 2026-01-01 --to 2026-12-31
history --file history.txt
report --file report.txt
export csv operations.csv --categories Еда
export json wallet-backup.json
import json wallet-backup.json --replace
```

Обе границы периода включены. Несуществующая категория вызывает понятную ошибку, пустая выборка — сообщение об отсутствии операций. Повтор категории в выборке не удваивает сумму. Для имени, содержащего запятую, используйте `--category "Имя, с запятой"`; `--category` можно повторять и сочетать с `--categories`.

Экспорт создаёт **новый** файл: существующие файлы не перезаписываются, родительский каталог должен существовать. JSON используется для обратного импорта; CSV — для просмотра и обработки отчёта. CSV-импорт не предусмотрен. Поля CSV экранируются, формулы в текстовых значениях нейтрализуются.

`--replace` явно подтверждает замену текущего кошелька. Перед импортом удобно сделать `export json backup.json`. Импорт проверяется целиком до изменения памяти. Операции межпользовательских переводов должны совпадать с текущими: нельзя восстановить одну сторону перевода и нарушить вторую. Для восстановления всех пользователей вместе используйте резервную копию `data/finance.json` при закрытом приложении.

## Правила учёта

- Одна валюта — RUB. `BigDecimal`, точность до копейки; ввод `1500.50` или `1500,50`. Сумма операции строго положительная и не больше `999999999999.99`. Ноль разрешён для бюджета.
- Логины: 3–32 латинские буквы, цифры, `_`, `-`. Логины и категории сравниваются без учёта регистра. Категорию нужно создать перед добавлением операции. Одна категория может содержать доходы и расходы, бюджет ограничивает только расходы.
- Бюджет действует **за всю историю**, без автоматического месячного сброса. Без фильтра остаток равен лимиту минус все расходы категории. В отчёте с периодом остаток рассчитан относительно расходов **этой выборки**, что явно подписано в выводе. Предупреждения всегда учитывают всю историю.
- Отчёт выводит доходы/расходы выборки и отдельно фактический баланс всего кошелька. Отрицательный баланс допустим при учёте расходов; приложение предупреждает об этом.
- Уведомления: расход достиг 80% бюджета, лимит исчерпан, превышен лимит, расходы превысили доходы, нулевой баланс. Проверяются после входа, операций, переводов, изменения бюджета и импорта, а также командой `alerts`.
- Перевод требует достаточного баланса, существующего получателя и запрещён самому себе. Создаются расход и доход в категории `Переводы` с общим `transferId` и логинами участников. Категория создаётся автоматически. Получатель увидит предупреждения при входе.

В [examples/demo.commands](examples/demo.commands) находится готовый сценарий регистрации и ввода всех данных ТЗ с учебным паролем. Запускайте в новом каталоге данных. В PowerShell 7:

```powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)
Get-Content -Encoding UTF8 examples/demo.commands | & "$env:JAVA_HOME\bin\java.exe" -jar target/personal-finance.jar --data-dir data/example
```

В Linux/macOS:

```sh
java -jar target/personal-finance.jar --data-dir data/example < examples/demo.commands
```

## Хранение и завершение

По умолчанию данные находятся в `data/finance.json`. При запуске файл читается и проверяется; после авторизации из снимка создаётся кошелёк нужного пользователя. Все дальнейшие вычисления выполняются в памяти.

`save`, `logout`, `exit`, `quit` и конец входного потока (EOF) сохраняют **всех** пользователей, включая получателей переводов. Регистрация, операции и импорт до сохранения находятся в памяти. Принудительное закрытие процесса или отключение питания может потерять несохранённые изменения; для промежуточного сохранения есть `save`.

Сохранение: временный файл в том же каталоге → запись и `force(true)` → атомарная замена. Оба кошелька перевода находятся в одном снимке. Если файловая система не поддерживает атомарное перемещение или нет прав записи, приложение сообщает об ошибке; обычный `exit`/`logout` при ошибке не закрывает сессию. При EOF ошибка сохранения даёт код завершения 1. Повреждённый файл не сбрасывается автоматически. Каталог защищён блокировкой от одновременной записи двумя экземплярами. Максимальный размер снимка — 20 МиБ.

Пароли хранятся как PBKDF2-HMAC-SHA256 (210 000 итераций), случайная соль 16 байт, хеш 32 байта. Финансовые данные в JSON не зашифрованы. `data/`, `exports/`, `target/` и локальные инструменты исключены из Git.

## Тесты и проверка оформления

```powershell
.\mvnw.cmd test             # unit- и интеграционные тесты
.\mvnw.cmd verify           # тесты, JAR и Spotless
.\mvnw.cmd spotless:apply   # автоматическое форматирование Java
```

На Linux/macOS замените `.\mvnw.cmd` на `sh mvnw`. Используются JUnit 5; тесты не трогают реальные кошельки, файловые тесты работают в `@TempDir`. Результаты: `target/surefire-reports/`. GitHub Actions запускает `verify` при push и pull request.

Последняя локальная проверка: **46 тестов успешно**, сборка и Spotless прошли. Подробности: [docs/VALIDATION.md](docs/VALIDATION.md).

Тестами покрыты пример ТЗ, точная арифметика, категории, бюджеты, пороги оповещений, выборки, авторизация, изоляция пользователей, переводы, JSON/CSV, повреждение файла, блокировка каталога, ошибки ввода и завершение CLI. Подробная карта требований: [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md).

## Структура и зависимости

```text
src/main/java/ru/promo/finance/
  Main.java        — сборка зависимостей и запуск
  core/            — модель, правила, сервисы и интерфейсы
  infra/           — JSON, CSV, пароли, файловая блокировка
  cli/             — команды, чтение ввода, форматирование
src/test/java/     — unit- и интеграционные тесты
examples/         — сценарий из ТЗ
docs/             — архитектура, критерии, публикация
.github/workflows/ci.yml
pom.xml
mvnw, mvnw.cmd, .mvn/wrapper/
```

Библиотеки: Jackson Databind и JavaTime 2.18.3 (JSON), JUnit Jupiter 5.11.4 (тесты). Плагины сборки: Compiler, Surefire, Shade (JAR с зависимостями), Spotless с Google Java Format. Версии закреплены в `pom.xml`. Wrapper использует Maven 3.9.9 и проверяет SHA-256 дистрибутива. Ручная установка библиотек не требуется.

Описание обязанностей каждого модуля и принятых решений: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Публикация на GitHub и сдача ментору: [docs/GITHUB.md](docs/GITHUB.md).
