# Архитектура

Приложение однопроцессное и однопоточное, с одной активной сессией. Слои разделяют предметную область, способы хранения и пользовательский интерфейс. Это консольный backend без HTTP и базы данных, как предусмотрено ТЗ.

## Модули

| Модуль / классы | Обязанности |
| --- | --- |
| `Main` | Composition root: пути, блокировка каталога, создание реализаций портов, выбор консольного ввода, запуск цикла |
| `core/Wallet` | Агрегат: категории и история, уникальные ID операций, неизменяемые снимки, ссылки операций на категории |
| `core/Category`, `Operation`, `OperationType` | Неизменяемые доменные значения; сумма, дата, направление, категория, комментарий, реквизиты перевода |
| `core/Validation` | Единые правила для денег, названий и логинов |
| `core/WalletSnapshot`, `AccountData`, `ApplicationState` | Версионированные снимки; проверка целостности при восстановлении |
| `core/FinanceService` | Регистрация, авторизация, текущая сессия, доступ только к своему кошельку, операции, переводы, сохранение и импорт |
| `core/ReportFilter`, `ReportService` | Чистые расчёты доходов/расходов по категориям и включительным границам дат |
| `core/AlertService` | Предупреждения по текущему состоянию всего кошелька |
| `core/StateRepository` | Порт чтения/записи полного состояния |
| `core/PasswordHasher` | Порт хеширования и проверки пароля |
| `infra/JsonFiles` | Jackson, UTF-8, строгая проверка JSON, лимит размера, создание экспорта без перезаписи |
| `infra/JsonStateRepository` | Атомарное сохранение всех аккаунтов в одном файле |
| `infra/Pbkdf2PasswordHasher` | Соль из SecureRandom, PBKDF2, сравнение хешей через MessageDigest.isEqual |
| `infra/DataDirectoryLock` | Межпроцессная блокировка каталога данных |
| `infra/CsvExporter` | CSV-отчёт, кавычки и защита текстовых ячеек от интерпретации как формул |
| `cli/CommandParser` | Разбор команды с кавычками и сохранением обратных слешей в путях Windows |
| `cli/FinanceCli` | Цикл команд, синтаксис, ошибки, запрос пароля и вызов сервисов |
| `cli/ReportFormatter` | Табличные сводки и история на русском языке |

`core` не импортирует `infra`, `cli`, Jackson или JUnit. Сервис получает хранилище, хеширование и `Clock` через конструктор. В тестах используется фиксированное время и хранилище в памяти. CLI получает источники ввода/вывода, поэтому проверяется без настоящего терминала.

## Жизненный цикл

1. `Main` получает эксклюзивную блокировку каталога.
2. Репозиторий читает `finance.json`. Отсутствующий файл означает новый пустой набор аккаунтов; повреждение означает ошибку запуска.
3. `FinanceService` хранит снимки аккаунтов в памяти. При успешном входе восстанавливает агрегат кошелька из снимка. Кошелёк получателя перевода также загружается при необходимости.
4. CLI проверяет форму команды, затем сервис и модель проверяют правила предметной области. Чтение и запись файлов при каждой операции не выполняются.
5. Сохранение строит единый снимок из изменённых кошельков и неизменённых аккаунтов. Репозиторий записывает его атомарно. Повторный вход в том же процессе сохраняет актуальное состояние из памяти.
6. Нормальный выход освобождает файловую блокировку. `exit` при ошибке сохранения возвращает управление в цикл, `logout` сохраняет активную сессию.

## Инварианты и решения

- Деньги представлены `BigDecimal` с двумя знаками. Точность не теряется из-за `double`; лишние значащие дробные разряды запрещены.
- Баланс вычисляется из истории. Отдельное изменяемое поле баланса отсутствует, поэтому он не может рассинхронизироваться с операциями.
- Имена категорий нормализуются для поиска через `Locale.ROOT`, но отображаемый регистр сохраняется. При переименовании обновляются все ссылки в истории. Удалять использованные категории запрещено.
- `null` в бюджете означает отсутствие лимита; `0.00` — установленный нулевой лимит.
- Период бюджета не задан в ТЗ, поэтому выбран бюджет за всю историю. В отчёте за период остаток — лимит минус расходы выборки; текущие предупреждения используют всю историю. Периодический сброс не выполняется.
- Для перевода сначала проверяются участники, сумма и достаточность средств. Изменения выполняются на копиях обоих кошельков; затем обе готовые копии заменяются в памяти. Обе стороны записываются одним файлом, общего `transferId` достаточно для связи. При загрузке проверяется парность, сумма, дата, направления и участники переводов.
- JSON-импорт сначала восстанавливает отдельный агрегат и проверяет его целиком. До успешной проверки кошелёк не меняется. Импорт одного кошелька не может добавлять, удалять или менять переводы.
- Лимит файла 20 МиБ защищает от случайно слишком большого импорта; это учебное приложение для локального использования, без пагинации и фоновых обработчиков.

## Формат хранения

Полный файл: `version: 1`, список `accounts`. У аккаунта поля `login`, `salt`, `passwordHash`, `wallet`. В кошельке: `version: 1`, `categories` и `operations`. Даты — ISO `YYYY-MM-DD`, суммы — JSON numbers без преобразования в `double`. Снимок экспорта содержит только кошелёк.

Схема версии 1 фиксирует алгоритм паролей. Изменение алгоритма или структуры требует новой версии и миграции; неизвестные версии не принимаются. JSON с дублирующими ключами, лишними полями, некорректными ссылками или повторяющимися логинами не принимается.

Принудительное завершение процесса до `save` не гарантирует сохранение. Это следствие модели «данные в памяти, сохранение при выходе»; команда `save` служит ручной контрольной точкой.

## Тестовая стратегия

- `WalletTest`: арифметика, категории, снимки, валидация, фильтры и границы дат.
- `FinanceServiceTest`: пример ТЗ, авторизация, изоляция, переводы, импорт, ошибки сохранения.
- `AlertServiceTest`: 80%, 100%, превышение бюджета, отрицательный и нулевой баланс.
- `PersistenceTest`: настоящие JSON/CSV-файлы в `@TempDir`, перезапуск сервиса, блокировка каталога, повреждения и версии.
- `FinanceCliTest`: поток команд и паролей, восстановление после неверного ввода, EOF, ошибки сохранения, таблицы и фильтры.

JUnit 5 запускается через Surefire, Spotless проверяет Google Java Format на этапе `verify`. GitHub Actions выполняет тот же цикл сборки на Java 17.
